2. How this module fits the repository

The platform is one Express API (modular monolith), one Python AI service and one React single-page app (SDD 6.2). This module is
therefore a set of folders inside those three applications, not a separate application. Each backend module folder holds its own
routes, controller, service, validators and models (SDD 6.5).

-   Backend (Node.js + Express): backend/
-   AI service (Python + FastAPI, Ollama, Scikit-learn, RAG): ai-service/
-   Frontend (React): frontend/

7. Dependencies on other modules

-   No dependency on the other modules. Every other module depends on this one for authentication, role checks, project context,
    notifications, audit logging and the AI gateway.

8. Notes, assumptions and open points

-   The SDD lists the notifications collection under the monitoring module (Table 28), while the SRS traceability table (Table 86)
    lists notifications under Platform and Administration. This scaffold follows the SRS: Platform owns the notifications module
    and every other module creates notifications by calling notifications.service.js.
-   The projects module is not assigned to a component in SRS Table 86. It is placed here because it is shared by all components
    (assumption).
-   Supervisor assignment mechanism is an open decision (SDD Appendix A, item 1). The projects module stores supervisorId either
    way; FR-ADM-014 requires recording who assigned the supervisor. No endpoint for assignment is defined in SDD Table 33, so none
    is scaffolded.
-   The SDD defines no endpoint for the Sub Admin to list all teams or to manage invalid project records (FR-ADM-008/009). The
    pages ProjectAdminPage and TeamAdminPage are scaffolded, but their endpoints must be added to the API design (proposal: under
    /admin).
-   Public certificate verification (no login) is an open decision (SDD Appendix A, item 4) and belongs to Module 5.

9. Suggested build order

1.  Environment, config, logger, error classes, constants.
2.  Express app, middleware chain (security, rate limit, authenticate, authorizeRole, validate, errorHandler).
3.  users + auth + token service; seedSuperAdmin script.
4.  projects module and projectContext middleware.
5.  notifications and audit log (needed by every other module).
6.  aiGateway (jobs, context builder, secret filter, validator) and aiServiceClient.
7.  AI service core: config, security, Ollama client, envelope, validation, health.
8.  Admin module (AI config, settings, stats, health, oversight).
9.  React shell: router, guards, API client, AuthContext, layout, dashboards, admin pages.
