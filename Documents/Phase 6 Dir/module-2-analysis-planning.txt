2. How this module fits the repository

The platform is one Express API (modular monolith), one Python AI service and one React single-page app (SDD 6.2). This module is
therefore a set of folders inside those three applications, not a separate application. Each backend module folder holds its own
routes, controller, service, validators and models (SDD 6.5).

-   Backend (Node.js + Express): backend/
-   AI service (Python + FastAPI, Ollama, Scikit-learn, RAG): ai-service/
-   Frontend (React): frontend/

7. Dependencies on other modules

-   Module 0: authentication, project context, aiGateway jobs, notifications (invitations), audit.
-   Module 1: consumes projects.selectedIdeaId.
-   Module 3: the approved baseline and approved timeline are the preconditions for plan generation (FR-EXE-001).
-   The effort-estimation model M2 is owned by Module 3 and is also called by /v1/planning/timeline.

8. Notes, assumptions and open points

-   Order conflict recorded in SDD Appendix A, item 6: the SRS lists timeline planning before team formation, but team size and
    member skills are planning inputs. Either start team formation before planning inputs, or accept a provisional team size that
    is updated when invitations are accepted (BR-PLN-2).
-   SDD Table 33 has no endpoint for answering clarification questions (FR-REQ-004). Proposal: send the answers in the body of
    POST /requirements/analyze, or add a dedicated answers endpoint (to be confirmed).
-   Sub Admin team actions are limited to administrative resolution, not ordinary team creation (SDD Appendix A, item 9).
-   A change to approved requirements requires re-approval and triggers a review of the timeline and plan (FR-REQ-010, BR-REQ-2).
-   Team members cannot modify the approved timeline (FR-PLN-008).

9. Suggested build order

1.  Teams and invitations (they feed planning inputs), with notifications.
2.  Requirements analysis endpoint, clarification loop, edit, approval and versioned baseline.
3.  Planning inputs and validation; scheduling.py and feasibility.py.
4.  M1: synthetic data, training, evaluation, predict, fallback.
5.  Methodology and timeline jobs; approval.
6.  Frontend pages in the same order; Supervisor review view.
