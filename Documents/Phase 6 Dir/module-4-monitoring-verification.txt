Module 4: Progress Monitoring and Deliverable Verification - Directory Structure

AI Project Supervisor (Module 1 of the larger platform) | Based on SRS v1.0 and SDD v1.0 | Draft for review

1. Module summary

  ---------------------------------------------------------------------------------------------------------------------------------
  Item                                                             Detail
  ---------------------------------------------------------------- ----------------------------------------------------------------
  Type                                                             Component 4 of 5

  Purpose                                                          Tracks progress, detects delays and blockers, accepts
                                                                   GitHub-based evidence, and verifies it against acceptance
                                                                   criteria. AI verification is static and advisory: the code is
                                                                   never executed, and a Supervisor can override a result with a
                                                                   recorded reason.

  Principal output                                                 Progress reports, alerts, recommendations and verification
                                                                   reports.

  Actors                                                           Student, Team Member, Team Leader, Supervisor, Sub Admin (view),
                                                                   Super Admin (inspect), AI Supervisor

  Use cases                                                        UC-09, UC-10, UC-11, UC-12, UC-13

  Workflows                                                        WF-12, WF-13, WF-14, WF-15, WF-16, WF-17

  Requirements                                                     FR-MON-001..015; FR-SUB-001..007; BR-SUB-1..2; FR-VER-001..015;
                                                                   BR-VER-1..4; AIV-001..004; EIR-004/011/013; MLR (M4 risk)

  MongoDB collections                                              progressSnapshots, blockers, aiRecommendations, submissions,
                                                                   verificationReports

  API groups                                                       Monitoring; Blockers; Submissions; Verification
  ---------------------------------------------------------------------------------------------------------------------------------

2. How this module fits the repository

The platform is one Express API (modular monolith), one Python AI service and one React single-page app (SDD 6.2). This module is
therefore a set of folders inside those three applications, not a separate application. Each backend module folder holds its own
routes, controller, service, validators and models (SDD 6.5).

-   Backend (Node.js + Express): backend/
-   AI service (Python + FastAPI, Ollama, Scikit-learn, RAG): ai-service/
-   Frontend (React): frontend/

7. Dependencies on other modules

-   Module 0: authentication, project context, aiGateway, notifications, audit, scheduler registration.
-   Module 3: reads phases, sprints and tasks; changes task status only through taskStatus.js.
-   Module 5 depends on this module: unresolved blockers count against completion (FR-MON-015) and every required deliverable
    needs an accepted verification status (BR-CRT-2).

8. Notes, assumptions and open points

-   GitHub is read by the Express API with a server-side GITHUB_TOKEN (SDD Table 38); the AI service receives only limited
    evidence excerpts, never the token.
-   The verification status is derived by fixed rules from criterion results, not from free text (FR-VER-005). Table 30 is marked
    Proposed in the SRS.
-   Inaccessible or insufficient evidence is never treated as verified (FR-VER-009). Submitted code is never executed
    (FR-VER-014).
-   Students and Team Leaders cannot mark an unverified deliverable as verified (FR-VER-013). The AI cannot override a Supervisor
    decision (AIS-004).
-   progressSnapshots, submissions, verificationReports and taskHistory are append-only (FR-AUD-002).
-   Only the Supervisor assigned to the project may review it (RBAC-007); the assignment mechanism is an open decision (SDD
    Appendix A, item 1).

9. Suggested build order

1.  Submission model, GitHub URL validation, upload middleware, versioning.
2.  githubClient and github module (access check, metadata, tree, files, rate limits).
3.  progressCalculator, snapshots, workload, alerts; monitoringScan job.
4.  M4 risk model and /v1/monitoring/analyze; recommendations and decisions.
5.  Blockers module logic.
6.  Verification: evidence selector, deterministic checks, criterion evaluator, statusRules, report.
7.  Supervisor review and override; resubmission; frontend pages in the same order.
